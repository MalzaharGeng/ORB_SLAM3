# 事故复盘：两次飞行的完整时间线

> 数据源：`data/flight_log/14_07_14.ulg` + `data/nanovio/Tm7tjC/`

**结论先行**：这一夜是**两个独立故障**叠加，不是一个问题。

| # | 故障 | 性质 | 证据强度 |
|---|---|---|---|
| 1 | **VIO 观测被门控拦截**（时钟 1970 为根因） | 软件/配置 | ★★★★★ 日志逐帧可查 |
| 2 | **电池负载下电压崩溃** | 硬件/物理 | ★★★★★ 飞控 ULog 实测 |

VIO 算法本身**没有问题** —— 用出事时的原始图像重算，286 帧里 **285 帧正常跟踪**（`tracking=2`）；拼接 127.7 秒数据重算，`tracking` 一次都没丢。

## 二、第一次飞行：漂移 102 米（t = 126 ~ 412 s，286 秒）

### 时间线

| t (s) | 事件 | 状态 |
|---|---|---|
| 126.1 | 解锁 | `armed=1`，`px4_local_frame_unready` |
| 135~145 | 手摇初始化 | `inertial_initializing`，高度 −1.48 m（原点在手上） |
| **147.5** | **VIO 开始发布** | `publishing`，`EV=1/1`，dH 0.05 |
| 165.7 | 切 POSCTL | `mode` 1→2 |
| 165~214 | 定点悬停 | x 2.5、y −0.1，**dH 0.00~0.15**，稳 |
| 214~228 | 真实机动 | vx 到 1.26 m/s，2 秒移动 2 m（物理合理，**不是跳变**） |
| 228~305 | VIO 帧率走低 | `reason` 多为 `waiting_new_frame`；同期 `rejected` 已累计 **1961 次** |
| **305.2** | **永久锁存** | `time_sync_unready` → `observation_gap` → `airborne_fault_latched` |
| 308.2 | **降级 ALTCTL** | PX4 主动放弃定点（位置失效） |
| 308~412 | **漂移** | y 从 −0.01 涨到 98.79 |
| 368.5 | EKF 二次崩 | 单帧 x=7.69 → **−28.20**（2 秒 36 m，物理不可能） |
| 412.9 | 上锁 | 位置 (−19.24, **102.25**) |

### 锁存瞬间的原始日志

```
[PX4] publishing        hz=14.96  sent=2176  EV=1/1/0     ← 一直正常
[PX4] time_sync_unready hz=14.99  sent=2186  EV=1/1/0     ← 时钟判定失效
[PX4] time_sync_unready hz=0.999  sent=2186  EV=0/0/0
[PX4] observation_gap   hz=0.999  sent=2186  EV=0/0/0     ← 观测间隔超限
[PX4] airborne_fault_latched      sent=2186               ← 锁存，sent 冻结
```

`sent` 从 2176 停在 2186，之后 `rejected` 一路涨到 1990。**VIO 从此一帧都发不出去。**

**补做证据（见 `05_正常段回放与基线.md`）**：用同一批图像离线重跑，305.2 s 前后逐帧 `valid=1 / tracking=OK / ba2=1`，位置从 (−0.01, −0.02, 0.05) 到 (−0.02, −0.02, 0.05)，连续无跳变。也就是说：**门控判死它的那一刻，它送出来的位姿是好的。** 问题在时钟判定，不在位姿本身。

### 因果链

```
nano 系统时间 1970（RTC 无电池，断电即复位）
  → 门控判 time_sync_unready（VIO 算出位姿但拒发）
  → 累积触发 observation_gap
  → airborne_fault_latched（永久锁存，只能落地 disarm 恢复）
  → PX4 失去视觉位置，POSCTL → ALTCTL
  → ALTCTL 无水平位置保持，摇杆只能控姿态
  → 漂移 102 m
```

```
  actuator_saturation = [0,0,0,0]  ✓ 无饱和
```

`-2`（UNDERTORQUE）只在起飞前和落地后出现，**飞行中一次都没有**。

```

rc_roll=−0.29 → 实测 roll=−11.2°
```

### 判断

飞机没有“飞出去”（位置只动 0.84 m），是在**原地剧烈摆动**。`rc` 杆在 ±0.3~0.5 之间来回，实测姿态 ±10~16°，属于人在追着修正的形态。

推力余量不足（电压见底 + 电机已到 0.80~0.85）+ 位置无保持（ALTCTL），所以打杆只能让它倾斜，无法有效平移。

## 四、VIO 独立评级：算法没问题

用出事瞬间的原始图像做离线重算，**同一批数据、同样的算法，结果完全不同**。

### 测试 A：`event_..._6`（锁存瞬间 286 帧）

| 指标 | 结果 |
|---|---|
| 有效位姿 | **285 / 286（99.7%）** |
| tracking 状态 | **`2`×285，`0`×1（仅第 0 帧）** |
| `ba2`（VIBA 2 完成） | **135 帧** |
| 位置范围 | x 2.54 m、y 2.67 m、z 3.07 m |
| 单帧最大位移 | 0.298 m（初始化收敛期） |

### 测试 B：6 个事件拼接（284~412 s，1091 帧，127.7 秒）

| 指标 | 结果 |
|---|---|
| 有效位姿 | **1060 / 1091（97.2%）** |
| tracking 分布 | **`2`×1090，`0`×1** |
| **`tracking` 从 2 掉出** | **0 次** |
| `ba2`（VIBA 2 完成） | **618 帧** |
| 位置范围 | x 3.44 m、y 1.61 m、z 6.30 m |

### 测试 C：事故前悬停段 `event_..._0`（284.15–304.13 s，285 帧）

| 指标 | 结果 |
|---|---|
| 有效位姿 | 269 / 285（94.4%） |
| tracking 分布 | `2`×284，`0`×1，**0 次 LOST** |
| `ba2` | **0 帧（全程未完成 VIBA2）** |
| IMU 初始化 | 被 `not enough motion` 打断 2 次，地图重建 3 次 |

**视觉能跟住，但惯性初始化定不下来。** 这是运动激励不足，不是算法错误 —— 详见 `05_正常段回放与基线.md`。

### 两次测试的差别说明什么

> **修订**：初版这里记录的是 105/286 与 43/1091，原因是格式转换时把 `imu.csv` 的加速度轴与角速度轴对调（`RollingInputRecording.cc:159` 的列序是 `t, ax, ay, az, gx, gy, gz`）。修正后几乎全程有效。

| 数据段 | 飞机动作 | 结果 |
|---|---|---|
| 284~412（拼接） | 悬停 + 被动漂移 | **1060/1091（97.2%），`tracking` 掉出 0 次** |
| 1352~1372（`_6`） | 手动大幅修正，动作激进 | **285/286（99.7%），全程正常** |
| 284~304（`_0` 单段） | 原地悬停 20 s | 269/285（94.4%），**VIBA2 未完成** |

**结论：VIO 算法正常，数据质量正常，跟踪几乎不丢。问题全部在“VIO → PX4”这一段。**

> 关于 `not enough acceleration`：它出现在 `run.log` 第 123~2188 行，即**初始化完成之前**。地面放置、电机不转时加速度恒为重力，初始化无法启动；一旦手摇（第 2194 行）35 行内即完成。空中机动段有姿态变化，能正常初始化（实验 A/B）。
>
> 补做实验 C 又划出一条边界：**空中原地静默悬停、只靠电机振动，同样会被判 `not enough motion`**，20 s 内 VIBA2 完不成。准确的说法是「需要足够的运动激励」，不是「需要离地」。

## 七、优先级与行动

| 优先级 | 问题 | 动作 | 影响 |
|---|---|---|---|
| **P0** | 电池负载下崩溃 | **换电池**，或做 20 A 放电测试 | 不解决，任何飞行都不受控 |
| **P1** | 系统时间 1970 | 做成开机自愈（fake-hwclock + uptime 推算） | 堵住 `time_sync_unready` 整条链 |
| **P2** | 锁存后不降落 | `airborne_fault_latched` 触发即刻 `NAV_LAND` | 本次若 305 s 降落，不会漂 100 m |
| **P3** | 门控阈值 | `max_age` 0.25→0.6，`stable_seconds` 1.0→0.3 | 减少 `sample_stale` / 反复清零 |
| **P4** | 滚动录制太短 | `rolling_seconds` 20→60 | 事件能回溯到初始化阶段，才可完整复现 |
| — | 一致性窗口 | 已改 1.0 s / 0.8 m，**保留即可** | 实际只触发 2 次，不紧急 |

### 关于“拉不回来”的准确归因

| 场景 | 机制 |
|---|---|
| 第一次（漂移到 102 m） | ALTCTL 无位置保持，摇杆只能控姿态，对抗不了持续漂移 |
| 第二次（原地摆动） | 推力余量不足（电量见底），打杆倾斜但无法有效平移 |

**不是遥控器失效。** `COM_RC_OVERRIDE=3` 已生效，`manual_enabled=1` 全程，姿态跟随一比一。
