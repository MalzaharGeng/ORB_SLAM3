# 门控缺陷清单

`Px4Vio.cc` 的门控层共 5 类判据，每一类都能把整场飞行判死。本文列出**门限值与实测数据的错配**，以及**故障处理策略的设计问题**。

数据来源：`data/nanovio/Tm7tjC/px4_telemetry.csv`（15 Hz，20657 行）与 `run.log`。

---

## 一、阈值错配

### 1.1 RTT 门限 20 ms（偏紧 19%）

```cpp
// Px4Vio.cc:153-154
if(!t.haveSync || !fresh(steady,t.syncSteadyUs,2000000) || t.roundTripUs>20000 ||
   std::abs(double(t.observedOffsetUs)-double(t.estimatedOffsetUs))>5000)
    return fail("time_sync_unready");
```

| 统计量 | 实测 | 门限 | 状态 |
|---|---|---|---|
| `sync_rtt_us` 最大值 | **23 794 us** | 20 000 us | **超 19%** |
| `sync_rtt_us` 在锁存帧 | **20 387 us** | 20 000 us | **超 387 us** |

**锁存就是被这 387 us 触发的。** 这不是时钟不准，是 DDS 往返延迟的正常抖动。

`timesync_status` 本身是健康的：

```
offset ≈ −936 ms，全程波动 < 1 ms，RTT 3~8 ms（典型值）
```

### 1.2 offset 残差门限 5 ms（偏紧 28%）

| 统计量 | 实测 | 门限 |
|---|---|---|
| `\|observed − estimated\|` 最大值 | **6 378 us** | 5 000 us |

出现在 t=407.1 s，与 t=303.22 的 RTT 超限是两条独立的触发路径。

### 1.3 帧间隔门限 300 ms（偏紧 256%）

`observation_gap` 的判据是相邻样本间隔。实测：

```
t=303.16  sample_us=535026064
t=304.22  sample_us=536027052   间隔 1001.0 ms   ← 3.3 倍门限
t=304.22  sample_us=536093811   间隔   66.8 ms
t=305.23  sample_us=537028390   间隔  934.6 ms
t=306.24  sample_us=538094965   间隔 1066.6 ms
```

**注意：这是间歇现象，不是常态。** 第一次飞行段（126~412 s）的 `sample_us` 更新间隔分布：

| 间隔 | 次数 | 占比 |
|---|---|---|
| < 100 ms（约 15 Hz） | 2034 | **87.6%** |
| 100~200 ms | 156 | 6.7% |
| 200~500 ms | 3 | 0.1% |
| **0.5~1.5 s** | **128** | **5.5%** |

中位间隔 66.7 ms，最大 1067.3 ms。

也就是说，**VIO 主体是正常的 15 Hz，但有 5.5% 的帧出现约 1 秒空洞**。而 `observation_gap` 门限是 300 ms，**任意一次空洞就足以触发锁存**。

### 1.4 为什么会出现 1 秒空洞

`VIO_PERF` 实测：`track_ms = 40 ~ 77 ms`，而 15 fps 的帧间隔是 **66.7 ms**。

| 指标 | 实测 | 需求 | 结论 |
|---|---|---|---|
| `track_ms` | 40~77 ms | < 66.7 ms | **77 ms 时处理慢于采集** |
| `ring_dropped` | 236 | 0 | 滚动录制也在丢帧 |

处理速度低于采集速度 → 队列积压 → 周期性跳帧。同期的 `ring_dropped=236` 说明整机资源已经吃紧。

### 1.5 `max_age_seconds` 250 ms（余量 60 ms）

| 统计量 | 实测 | 门限 |
|---|---|---|
| `age_ms` 峰值 | **190 ms** | 250 ms |

余量只有 60 ms。VIO 周期一旦从 66.7 ms 掉到 5.5 Hz（182 ms，历史实测），余量就归零。

## 二、故障处理策略

### 2.1 五条路径全部一次性永久锁存

```cpp
// Px4Vio.cc:155-158
if(airborneFault_) {
    if(t.armed) return fail("airborne_fault_latched");
    airborneFault_ = false; Reanchor();
}
```

**只要还在 armed，就永远锁存。** 能置位 `airborneFault_` 的路径有 5 条：

| 行号 | 触发条件 | 判据 |
|---|---|---|
| 137 | PX4 local reset 变化 | `xy/z/heading_reset_counter` 变化 |
| 143 | 参考系/时钟纪元变化 | `referenceEpoch` 或 `clockEpoch` 变化 |
| 150 | 样本时间戳倒退 | `clockFault` |
| 160 | 时间戳为 0 或在未来 | `!s.sampleUs \|\| age_ < −0.005` |
| 195 | 运动门控 | 超速 / 位置速度不一致 / 帧间隔 |

**每一条都是"单次越界即判死"，没有"丢弃该帧、下一帧继续"的路径。**

### 2.2 后果

以本次为例：

```
1 秒帧空洞（可自愈）
  → observation_gap（第 195 行 motionFault）
  → airborneFault_ = true
  → 之后每一帧都 return fail("airborne_fault_latched")
  → sent 冻结 2186
  → PX4 失去视觉位置
  → POSCTL 降级 ALTCTL
  → 漂移 102 m
```

**一个 1 秒的瞬时抖动，换来了 100 米的漂移。**

### 2.3 建议改法

| # | 改动 | 理由 |
|---|---|---|
| 1 | `roundTripUs` 20 ms → **50 ms** | 实测最大 23.8 ms |
| 2 | offset 残差 5 ms → **15 ms** | 实测最大 6.4 ms |
| 3 | `observation_gap` 300 ms → **1500 ms** | 实测出现 1.07 s |
| 4 | `max_age_seconds` 250 ms → **600 ms** | 与 `observation_gap` 配套放宽 |
| 5 | **锁存分级**：单帧异常丢弃，连续 N 次（建议 30 帧 = 2 s）才锁存 | 5 条路径都缺降级 |
| 6 | 锁存后**立即 `NAV_LAND`** | 本次若 305 s 降落，不会漂 100 m |
| 7 | 降 `nFeatures` 或 fps，让 `track_ms` < 50 ms | 77 ms vs 66.7 ms |

前 4 条改阈值，第 5、6 条改逻辑，第 7 条要重新做性能测试定值。

### 2.4 修正：`ba2` 判据其实存在；真正的缺口是锁存分级与告警

**修订（2026-11-06）**：此前本节写“门控质量判据只有一个 bool”，是 grep 漏检所致——字段名是 `s.ba2` 不是 `inertialBA2`。实际源码（`src/Px4Vio.cc:176`）：

```cpp
if(!s.imuInitialized || !s.ba2)return fail("inertial_initializing");
```

也就是说 **VIBA2 未完成的位姿本来就不会被发布**，N0 悬停段那种 `ba2=0` 的帧在实机会被这条拦住。这一条是好的，不用改。

真正缺的是两件事：

1. **`time_sync_unready` → 拒帧 → `observation_gap` → 锁存**这条链没有任何分级（见 §2.1/2.2）；
2. **发布期间无质量告警**：第一次飞行 `rejected` 累计 1961 次、5 段内录的触发原因都是 `time_sync_unready`，但没有任何日志级别提升或提前降落建议——问题在演变成锁存之前是完全可见的。

## 三、验证方式

### 3.1 确认阈值是主因

```bash
grep -a '\[PX4\]' data/nanovio/Tm7tjC/run.log \
  | tail -400 \
  | grep -aE "time_sync_unready|observation_gap|airborne_fault|publishing"
```

应当能看到：`publishing` → `time_sync_unready` → `observation_gap` → `airborne_fault_latched` 的完整序列，且 `sent` 在锁存后不再增长。

### 3.2 确认处理速度临界

```bash
grep -a 'VIO_PERF' data/nanovio/Tm7tjC/run.log \
  | sed 's/.*track_ms=\([0-9.]*\).*/\1/' \
  | sort -n | tail -5
```

如果最大值超过 66.7，说明每 15 帧至少丢 1 帧。

### 3.3 确认样本间隔突变

```bash
python scripts/check_sample_gap.py data/nanovio/Tm7tjC/px4_telemetry.csv
```

输出 `sample_us` 的相邻间隔，应能看到从 66.7 ms 突跳到 1000 ms 的时刻。
