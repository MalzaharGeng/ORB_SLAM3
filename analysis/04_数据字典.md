| 值 | 含义 |

## 二、`run.log`（SLAM 控制台全量）

### `[PX4]` 行格式

```
[PX4] <reason> hz=<f> age_ms=<f> sent=<n> rejected=<n> overwritten=<n> armed=<n> mode=<n> EV(pos/hgt/vel)=<n>/<n>/<n> local_valid=<n>
```

`hz` 是 VIO 输出频率，`sent` 只增不减；**`sent` 停止增长 = 不再发布**。

### `VIO_PERF` 行格式

```
[VIO_PERF] track_ms=<f> features=<n> tracking=<n> map=<n> epoch=<n> ring_dropped=<n> capture_hz=<f> process_hz=<f> gyro_hz=<f> accel_hz=<f> clock_rejected_total=<n>
```

| 字段 | 含义 | 正常范围 |
|---|---|---|
| `track_ms` | 单帧跟踪耗时 | **< 66.7**（15 fps 的帧间隔） |
| `features` | 提取特征数 | 1000 ± 10 |
| `tracking` | 0=未初始化, 1=刚初始化, 2=正常, 3=LOST | 2 |
| `process_hz` | 处理频率 | 14.6~15.0 |
| `ring_dropped` | 滚动录制丢帧累计 | 0 |

### `[RollingInput]` 行

```
[RollingInput] EVENT <reason> frames=<n> path="<事件目录>"
```

事件触发时冻结 20 秒环形缓冲，落盘到 `/home/nano/vio_image_events/`。

## 四、坑（必读）

### 坑 1：`system_us` 是 1970 基准

nano 无 RTC 后备电池，每次断电复位到 1970。所有时间戳都要减首行才是相对时间：

```python
t0 = float(rows[0]["system_us"])
t  = (float(r["system_us"]) - t0) / 1e6   # 秒
```

### 坑 2：`inrec_*.csv` 的 `bridge` 行位置列错位

内录文件里 `src=bridge` 的行，`y` 列被写成了微秒时间戳、`vx` 是递增计数器、`x` 是截断的整数台阶。**位置数据不可用，只有标志位可信。**

分析位姿请用 `src=vio` 的行。

### 坑 3：内录的 `armed` / `nav_state` 恒为 −1

`vio_inrec.py` 没有订阅 PX4 状态，所以**不能从内录判断是否解锁**。需要看 `px4_telemetry.csv`。

### 坑 4：目录名的时间是假的

系统时间 1970 时，run 目录名是 `19700101_080351_live_Tm7tjC`，其中 `080351` 是 **uptime 8 分 3 秒**，不是真实时刻。

用 `ls -t` 排序也会错乱（1970 的目录会排到最后）。**正确做法：从进程 cmdline 读当前 run 路径**：

```bash
p=$(pgrep -f 'stereo_inertial_realsense_D435[i]' | head -1)
dirname "$(tr '\0' '\n' < /proc/$p/cmdline | grep 'recordings/test_runs/' | head -1)"
```

### 坑 5：replay 要求 index 从 0 连续

`ReadInputRecording()` 有硬校验：

```cpp
require(count(r[0]) == result.frames.size(), "frame index gap");
```

滚动录制的原始帧号（如 19613）会直接报错，必须先重编号为 0..N−1。

### 坑 6：滚动录制格式与 replay 格式不同

| | 滚动录制 | replay 要求 |
|---|---|---|
| 格式标识 | `ORB_SLAM3_ROLLING_INPUT_V1` | `ORB_SLAM3_STEREO_INPUT_V1` |
| 帧索引 | `frame_xxx/frame.csv`（4 列） | `stereo.csv`（5 列） |
| IMU | 每帧一个 `imu.csv` | 根目录一个 `imu.csv` |
| 图像 | `frame_xxx/left.png` | `left/*.png` |

必须用 `scripts/convert_rolling.py` 转换。

### 坑 7：滚动录制的 `imu.csv` 是「加速度在前」

`RollingInputRecording.cc:159`：

```cpp
imu << m.t << "," << m.a.x() << "," << m.a.y() << "," << m.a.z()
    << "," << m.w.x() << "," << m.w.y() << "," << m.w.z() << "\n";
```

列序是 **`t, ax, ay, az, gx, gy, gz`**，而 `InputRecording`（标准录制）是 `frame, t, ax, ay, az, gx, gy, gz`。两者一致，**转换时不要重排**。

校验：`|a| = sqrt(ax²+ay²+az²)` 应约 **9.8 m/s²**。如果算出来是 1~2，说明把角速度当成加速度了。

另：`frame.csv` 四列是 `id, timestamp(图像), steady_clock, imu_count` —— 第 3 列是单调时钟，不是第二个图像时间戳。

### 坑 8：`actuator_motors` 的 `control[0]` 不是电机 1

pyulog 解析时 `control[0]` 装的是 `timestamp_sample`。实际电机从 `control[1]` 开始。

## 五、坐标与符号

| 项 | 约定 |
|---|---|
| 坐标系 | NED（x 前、y 右、z **向下为正**） |
| 高度 | `z < 0` 表示在原点**上方** |
| 四元数顺序 | PX4 为 `w, x, y, z` |
| 电池 | 6S（`cell_count=6`），满电 25.2 V，过放线约 19.8 V |
| 姿态单位 | 度（本文档统一转换） |

### 坑 8：多段拼接会让 IMU 样本重复或断档

六段滚动录制每段 20 s，而事件间隔 10~19 s，所以相邻段有大段重叠。

- 直接拼：重叠区帧重复，replay 会按重复时间戳推进两次；
- 只丢重复帧：它带着的 IMU 批一起丢，重叠区出现 20~60 ms 空洞；
- 两边都留：同一 IMU 样本被预积分两次，直接算错。

`scripts/replay_splice_rolling.py` 的做法：丢重复帧，但把它携带的、**晚于前一保留帧末样本**的 IMU 追加给前一帧；每个保留帧的 IMU 批只保留严格晚于前一批末样本的样本，保证全局时间单调且不重复。

## 五、replay 输出字段（`navigation.csv` / `timing.csv`）

`navigation.csv`（21 列中的前 14 列，逐帧一行）：

| 列 | 来源 | 含义 |
|---|---|---|
| `index` | 重排后的帧号 | 0..N−1 |
| `timestamp` | 图像时间戳 | 秒，D435i 时钟，与遥测 `t` 同一时间轴（误差 < 1 s） |
| `valid` | `NavigationState.valid` | 位姿是否可用（**门控唯一使用的字段**） |
| `tracking` | `trackingState` | -1 未就绪 / 0 无图像 / 1 未初始化 / **2 OK** / 3 刚丢 / 4 LOST / 5 OK_KLT |
| `imu` | `inertialInitialized` | IMU 初始化是否完成 |
| `ba2` | `inertialBA2` | **VIBA2 是否完成**（尺度/重力收敛标志） |
| `first_map_frame` | `inFirstMap` | 是否仍在首张地图（重建后为 0） |
| `imu_x/y/z` | `imuToWorld` 平移 | VIO 世界系（原点 = 首帧 IMU 位置），**各次初始化独立** |
| `qw/qx/qy/qz` | `imuToWorld` 旋转 | 同上 |

`timing.csv`：

| 列 | 含义 |
|---|---|
| `read_ms` | PNG 解码耗时，**回放器特有**，实机无此开销 |
| `track_ms` | `TrackStereo()` 实际耗时，含锁等待 |
| `cycle_ms` | 整帧周期（read + track + 写盘等待） |
| 帧间隔 | 640×480@15fps ≈ 66.7 ms，`track_ms` 超过它就意味着处理慢于采集 |

> 注意：`valid=1` 不代表位姿准。实验 C（悬停段）里 `valid` 94.4%、`tracking` 99.6% OK，但 `ba2` 全程 0 —— 尺度和重力方向都还没收敛。判断"能不能用"至少要同时看 `ba2`。
