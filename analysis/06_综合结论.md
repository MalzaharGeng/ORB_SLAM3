| heading | 0.5°，此后开始随 VIO 漂移（后文见 38.7°） |

**阶段 3 · 定点悬停（165.9–308.0，POSCTL）**

这一段是"跟遥控器抢杆"的发生地。数值证据：

| 项 | 数值 | 含义 |
|---|---|---|
| 摇杆 | **99.3% 时间回中**（\|roll\|>0.1 仅占 4.7%） | 人基本没动杆 |
| 位置 setpoint | 回中时移动速度 **p50 = 0**；全程移动 x 4.47 m、y 2.63 m | setpoint 只在打杆时移动 |
| EKF 实际位置 | 回中时漂移速度 **p50 0.040 / p90 0.276 / max 1.89 m/s** | 摇杆没动，飞机却在漂 |
| EKF 位置范围 | x 1.44–6.19、y −2.24–0.61 | 定点锁不住，4–6 m 范围内游走 |
| heading | 0° → 最大 **+58.7° / −45.8°** | 航向在定点期间大幅摆动 |
| 门控 | `rejected` 从 0 累计到 1961（280 s） | EV 样本被时钟门控断续拒收 |

机制：POSCTL 的位置环全程在工作，它相信的参考位置来自 VIO；VIO 的参考系被时钟问题折磨（样本断续被拒、参考系带偏），EKF 位置一漂，位置环就输出姿态修正把飞机往"错误的位置"拉——**这就是与遥控器抢夺控制的真凶，不是 VIO 停发之后才抢，恰恰是 VIO 还在发（但质量受损）的时候**。

**阶段 4 · 锁存与自动降级（304.0–308.0）**

| t | ULog 值变化 | 说明 |
|---|---|---|
| 304.0 | `dead_reckoning` **0 → 1** | EKF 自己宣布"位置不可信，改纯推算"——比锁存还早 4 s |
| 307.9 | `xy_valid` **1 → 0** | 水平位置失效 |
| 308.0 | nav_state **POSCTL → ALTCTL** | **PX4 自动降级，不是人切的** |
| 同时 | EKF 位置 (3.01, −0.01)、heading 38.7° | 位置本身还没崩，是"可信度"没了 |

**阶段 5 · ALTCTL 漂移段（308–412.9）——"拉不回来"的真相**

| t | 事件 | 数值 |
|---|---|---|
| 337–339 | **yaw 杆只打了 2 秒**（−0.51） | 机头 +38.7° → −37.5°，**转了 76.2°**，此后航向保持 −37.5° 直到落地 |
| 340 | 用户开始持续拉杆 | rc_roll 最大 0.33 → 实际 roll 仅 ~6°（倾角小，加速度 ~1 m/s²） |
| 368.5 | EKF 位置单帧跳变 | x 7.69 → −28.20（纯 IMU 推算发散） |
| 412.9 | 上锁 | EKF (−19.40, **102.31**)，heading −36.2° |

ALTCTL 没有水平位置环，**这一段不存在"抢夺"**。"拉不回来"是三件事叠加：
1. **航向偏了 76°**：按旧航向记忆打杆，方向全是错的；
2. **倾角小**：杆量 ±0.42 只能压出 ~6° 倾角，推力水平分量不足以刹住漂移速度；
3. **没有位置保持**：ALTCTL 下飞机带速度就继续滑，且夜间没有地面参照。

`3003_0..5` 六段内录正好覆盖 284–412 s（即阶段 3 尾部→阶段 5 全程）。对这批图像的三组回放：

| 回放 | 数据 | valid | tracking | ba2 | 说明 |
|---|---|---|---|---|---|
| N0 | 悬停段 284–304 s 单段 | 94.4% | OK 99.6%，0 LOST | **0%**（VIBA2 未完成） | 悬停冷启动初始化不了——能力边界 |
| NA | 六段拼接 1091 帧 | **97.2%** | **OK 99.9%，0 LOST** | 56.6%（首帧后 18.9 s 完成） | 锁存时刻前后 VIO 位姿连续无跳变 |

**阶段 5 里 VIO 的直接证据**：305.2 s（锁存帧）前后逐帧 `valid=1 / tracking=OK / ba2=1`，位置 (−0.01, −0.02, 0.05) → (−0.02, −0.02, 0.05)。**门控判死它的那一刻，它送出来的位姿是好的。**

关键观察（2026-11-06 02:0x 修订——依据 nano run.log 行 6301–6310，此前漏检）：
1. **全程 ALTCTL、`xy_valid=1` 直到落地**——整个 44 s 飞行期间 EV 持续被 EKF 融合，定位一直有效。
2. **VIO 重放 99.7% 有效**（第一节），与飞控侧一致。**炸机原因与 VIO 无关**——迫降操作与遥控指令相符；低电压的直接因果证据不足，见 analysis/07。
3. **但炸机的最后一瞬，VIO 又被锁存了一次**：nano `run.log` 行 6301–6307（图像时间 1372.8 s，上锁前 0.2 s）：

```
[PX4] cumulative_position_velocity_inconsistent ... sent=16308 armed=1   ← 落地撞击瞬间，窗口一致性超限
[PX4] airborne_fault_latched ... sent=16308 armed=1                      ← motionFault 立即永久锁存
[RollingInput] EVENT airborne_fault_latched frames=286 .../event_..._3003_6
[PX4] stabilizing ... armed=0                                            ← 0.2 s 后上锁
```

   落地撞击使 VIO 位置/速度窗口残差超限 → `cumulative_position_velocity_inconsistent` → **无分级的 motionFault 立即永久锁存** → VIO 停发 → 0.2 s 后上锁。这是**落地撞击的伴随事件，不是炸机原因**——但它恰好再次演示了"单次异常即永久判死"的设计缺陷：连落地这种正常物理事件都会触发锁存。修复清单第 3 条（motionFault 连续 30 帧才锁存）直接覆盖此问题。
4. 飞机全程在 102 m 漂移点附近 1.5 m 内活动，高度 0.7–2 m 低空，油门杆操作正常。
5. 归档之外另有两个内录事件（nano `vio_image_events/`）：`event_1793809142759030_103610_0`（reason=review6_validation，地面验证测试）与 `event_unclean_1793809046332312864`（reason=unclean_exit，OxvpHk 运行异常退出落盘）——均为地面产物，与炸机无关。

## 四、总结论（五条）

1. **三段内录重放（悬停段 / 前段拼接 / 事故段）tracking 全部 0 次 LOST，valid 94.4–99.7%。** VIO 算法与输入数据在这三次飞行里没有出过错。唯一受限的是"纯悬停冷启动"——20 秒内 VIBA2 完不成（运动激励不足），这是能力边界不是故障。
2. **第一次飞行"抢杆"的真凶是 POSCTL 位置环 + 受损的 VIO 参考**：摇杆回中 99.3% 的情况下飞机以最高 1.89 m/s 漂移，位置环全程在追假位置。抢杆发生在 VIO 还在发布（但质量受损）的时段，不是停发之后。
3. **VIO 停发后不存在抢夺**：锁存后 PX4 自动降级 ALTCTL（`xy_valid=0` 同帧），该模式没有水平位置环。"拉不回来"是因为 yaw 杆 2 秒让机头转了 76°、倾角只有 ~6°、且没有位置保持——是操作感知问题 + 模式能力问题，不是控制器对抗。
4. **最后一次炸机与 VIO 无关**：全程 `xy_valid=1`、EV 融合到落地，VIO 重放 99.7% 帧有效。低电压告警 6.7 s 置位而 COM_LOW_BAT_ACT=0 未动作；迫降操作与遥控一致，直接因果证据不足（见 analysis/07）。
5. **需要修的还是那两件事**：开机时钟自愈（消除 `time_sync_unready` 的源头）+ 门控降级策略（单帧异常丢弃、连续 N 次才锁存、锁存即 `NAV_LAND`）。VIO 本身不需要动。
