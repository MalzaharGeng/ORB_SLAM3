# Git 协作规范

本规范按出处区分仓库明文要求、远端结构事实和工程写作惯例，避免将历史做法误作普遍规定。

## 仓库明文要求

### 提交与推送

[构建配置实施计划](plans/2026-11-08-build-profiles.md) 第 8 条：

> 代码、CI配置、文档分开提交，提交说明记录本地构建/测试数量及未验证边界。推送前 fetch 防止覆盖远端新增提交，普通 fast-forward 推送，回读引用与文件哈希。

计划目标段要求两分支分别提交、不合并分支；结尾要求不删除数据集大文件或改写历史。
这些条文原用于构建工作，以下为后续协作采用的执行方式：

- 代码、CI 配置、文档分别提交；没有 CI 变更时不创建空提交。忽略规则等仓库配置另作配置提交。
- 提交说明记录环境、实际构建次数、测试数量和未验证边界。
- 推送前 fetch，核对目标引用；远端出现新增提交时先核实，不覆盖远端。
- 只作普通 fast-forward 推送，不强推、不改写已发布历史；修正通过追加提交完成。
- 推送后回读远端引用，核对提交 ID 和改动文件的 SHA256。

### 数据与环境

根 [README](../README.md) 的“运行环境与同步边界”要求源码、配置文本与运行环境、依赖及构建产物分离。
内录、备份和构建产物不进入代码主线；Windows/Linux 比对前需排除行尾差异。
数据目录与数据分支承担原始记录的保存，不以仓库清理为由删除数据集或改写历史。

## 远端结构事实

远端默认分支为 master，分支角色如下。平台角色来自环境文档，不由分支名称推导。

| 分支 | 角色 |
|---|---|
| master | 第一长期线，x86 / WSL / Lyrical |
| nano | 第二长期线，aarch64 / Humble / 实机 |
| nano-crash-20261103 | 事故代码快照 |
| nano-crash-20261105 | 事故代码快照 |
| data/first-crash-20261103 | 首次事故数据 |
| data/second-crash-20261105 | 第二次事故数据 |
| nano-test-data | 测试数据 |
| archive/nano-deploy-20261106 | 历史部署归档 |
| site | 站点内容 |

Git 分支是提交引用，不保存“父分支”属性。共同祖先不等于现有分支之间的直接父子关系。

工程内容按以下方式安排：

- master 和 nano 分别维护；共享修改按同源补丁核对并分别提交，不合并两条长期线。
- 事故与测试数据使用独立分支，或明确安排的 data/ 目录；原始录制不混入主线源码。
- 解释性 HTML 放 site 分支，不混入主线代码。
- refs/heads/nano 已占用引用路径，因此不能同时创建 nano/xxx。事故分支使用 nano-crash-日期。
- 保留既有归档、上游资料、许可证和历史数据。

## 工程写作惯例

这一节属于写作口径，不作为对早期提交格式的追溯要求。

- 采用中文工程记录口吻，陈述问题、实际修改、参数和验证结果。
- 写清构建、测试数量，以及“未实机飞行”“未在 aarch64 编译”等具体边界。
- 不用星级、评分、emoji、宣传性或模板化措辞。
- 提交可读源码、配置和必要的文本证据；不新增压缩打包交付物，既有词典包、资料和数据分支保留。

格式示例：

- [742b113](https://github.com/MalzaharGeng/ORB_SLAM3/commit/742b1132bcb605d5598686c8dd5a19f51442ba9f)：记录帧率、功耗模式与未验证范围。
- [a8855f2](https://github.com/MalzaharGeng/ORB_SLAM3/commit/a8855f2e6418abe9c465ba997aa8d6bf4c0a476c)：记录行尾问题、实际差异与未重新编译的边界。

## 忽略规则

根 .gitignore 以三段规则起头：

~~~gitignore
*
!*.*
!*/
~~~

默认忽略无扩展名文件，重新放行带点名称的文件和目录；后续条目仍可再次忽略。
带扩展名不代表应当提交：运行日志、录制、备份和二进制也可能带扩展名。

无扩展名脚本使用精确的 !完整路径 例外，并确保父目录可遍历。检查方式：

~~~bash
git check-ignore -v path/to/new_file
git status --short --untracked-files=all
~~~

不要为加入脚本整体放行构建目录，不将 git add -f 代替长期忽略策略。
.gitignore 不会自动移除已跟踪文件；保留已发布资料和数据。

## 跨平台行尾

仓库内 LF 与 CRLF 并存，例如 CMakeLists.txt 使用 LF，nano/README.md 使用 CRLF。
不能依赖本机 core.autocrlf 默认值推断原始 blob。

1. 修改前使用 git show HEAD:path 读取原始字节，确认行尾和权限。
2. 跨平台语义比对可先剥回车；落盘时保留目标文件原有行尾，不混用会翻转行尾的工具。
3. 修改后检查 git diff --numstat；增删行数接近整文件行数时，先排查行尾转换。
4. git diff --check 的 CRLF 提示须结合原始 blob 判读，不为消除提示而批量改全树。
5. 确需统一行尾时单独说明、单独提交，并验证归一化后内容不变。

## 执行顺序

1. 确认目标长期线、环境、远端起点；有未提交工作时优先使用独立 worktree。
2. 保留原有行尾和权限，完成修改；源码与录制、备份、构建目录分开。
3. 在声明的环境执行适当构建和测试，记录数量和未验证范围。
4. 按代码、CI、文档或仓库配置分别提交，说明采用中文事实表述。
5. fetch 并核对目标引用，使用普通 fast-forward 推送。
6. 回读远端引用和文件 SHA256。

## 性能验证边界

每目 1280×960、ORB 配置 1000 特征保持不变。GPU 或并行实现需同时比较耗时、
关键点与描述子或匹配差异、回放跟踪质量。相机输入帧率与 SLAM 处理帧率分别报告。
静态运行、故障注入和录制回放不能替代需要真实运动的标定或实飞验收。
