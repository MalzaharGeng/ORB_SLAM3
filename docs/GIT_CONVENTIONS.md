# Git 约定

## 分支

| 分支 | 用途 |
|---|---|
| `master` | 默认分支，x86 / WSL 开发 |
| `nano` | Jetson Orin Nano / aarch64 / Humble 实机工程 |
| `nano-crash-20261103`、`nano-crash-20261105` | 事故代码快照 |
| `data/first-crash-20261103`、`data/second-crash-20261105` | 事故原始数据与分析 |
| `nano-test-data` | 测试数据 |
| `archive/nano-deploy-20261106` | 历史部署归档 |
| `site` | 站点内容 |

`master` 和 `nano` 分别维护，共享修改核对后分别提交，不合并两条长期线。
设备写入和部署需单独授权。分支不是环境镜像，依赖、构建目录与二进制不能跨架构搬运。
`nano` 已占用引用路径，其他相关分支使用 `nano-xxx`，不能使用 `nano/xxx`。

## 提交与推送

1. 确认目标分支和远端起点，保留已有未提交修改。
2. 按代码、CI、文档和仓库配置分别提交，不创建空提交。
3. 提交说明使用中文，写明实际修改及验证结果。未执行的构建或测试不记为通过。
4. 推送前 fetch 并检查远端新增提交，只作普通 fast-forward 推送。
5. 推送后回读远端提交和改动文件，核对内容。

不强推、不改写已发布历史，不以整理仓库为由删除原始数据。
上述提交方式沿用 [构建实施计划](plans/2026-11-08-build-profiles.md) 的约定。

## 文件与数据

源码、配置和必要的文本记录进入代码分支；原始录制、备份、依赖及构建产物放在对应数据分支或设备目录。
保留上游文档、许可证、已有词典包和历史数据。文档写清具体参数、环境、日期与结果，删除重复说明和宣传性措辞。

当前常驻处理为每目 **960×720、nFeatures 1000**，全尺寸标定和历史性能对照见 [处理配置](RESOLUTION_PROFILES.md)。
报告性能时区分相机输入帧率、SLAM 计算耗时和服务实际帧率。静态运行与回放结果不能替代实飞精度验证。

## 忽略规则

根 `.gitignore` 先忽略无扩展名文件，再放行带点名称和目录，后续规则仍可再次忽略。
无扩展名脚本使用精确路径例外，不为加入脚本整体放行构建目录。

```bash
git check-ignore -v path/to/new_file
git status --short --untracked-files=all
```

`.gitignore` 不会移除已跟踪文件。新增文件应逐项检查，不用 `git add -f` 代替长期忽略规则。

## 行尾

仓库中 LF 与 CRLF 并存，修改时保留原文件行尾和权限。
先用 `git show HEAD:path` 检查原始字节；修改后检查 `git diff --numstat` 与 `git diff --check`。
整文件增删时先排查行尾转换，跨平台语义比较可先去除回车。
确需统一行尾时单独提交，核对归一化后内容一致。
