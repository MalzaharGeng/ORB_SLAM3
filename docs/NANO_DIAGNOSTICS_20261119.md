# Nano 故障记录与初始化地图保护

本次将已在 Nano 部署的三项修改同步到 `nano` 分支：保留首次故障现场、细化 IMU 区间覆盖诊断、检测初始化优化期间的地图身份变化。相机标定、惯性初始化要求、发布门控和五米任务参数未调整。

## 首次故障现场

`Gate` 在清空比较窗口或参考变换前，按值保存当前/上一帧、源时间、位置、速度、姿态、地图变换、参考版本、PX4 状态和 reset 计数，以及残差和相关门限。

桥接器在自己的工作线程中，将快照写入 `<log_path>.faults.jsonl`；控制台同时输出 `[GATE_FIRST_FAULT]`。每个进程最多写入首次故障与首次锁存两个快照，后续故障不会覆盖它们。正常启动等待不会占用快照，非有限数值序列化为 JSON `null`。这项记录不改变拒绝、发布、锁存或恢复规则。

## IMU 区间诊断

`[IMU]` 状态和退出前的 STOP 行新增：

- 图像请求的 `requested_start_s`、`requested_end_s`。
- 切片消费前的 `imu_first_s`、`imu_last_s` 与缓冲条数。
- `history_covered`、`future_covered` 及两端缺口毫秒数。
- 最后接收/接受样本年龄与本次等待耗时。

`waiting_imu` 表示当前缓冲尚未覆盖请求区间，不单独证明物理串口断线。数据被拒或源时间发生间断时，不再将最近回调状态统一显示为 `ok`。35 ms 等待、30 ms IMU 源时间间隔和原有拒绝/退出行为保持不变，不补造缺失数据。

## 初始化地图身份

`InitializeIMU` 捕获所属地图指针、ID及起始关键帧，在优化前后和结果提交边界核对它们；优化与明确的地图写入目标固定为原所属地图。检测到换图、原地清空或关键帧所属变化时，放弃该次初始化并输出 `IMU_INIT_ABORT`。

这没有开启未成熟地图保留、没有缩短 VIBA1/VIBA2，也不宣称所有并发重置竞争均已消除。实际地图对象的身份回归覆盖换图、复用ID、ID变化、原地清空、起始关键帧替换和新初始化。

## 构建与测试

```bash
ctest --test-dir build --output-on-failure \
  -R '^(initialization_map_identity_regression|imu_coverage_regression|nano_fault_evidence_regression)$'
```

`tests/nano_gate_parity.cc` 是同一输入驱动，分别链接旧/新核心后比较24类场景、3840次评估的发布决策、健康状态与观测数值；它不是依赖两个版本的普通单版本 CTest。

Nano 上使用当前前端优化对象和已有依赖进行隔离增量构建，未覆盖旧部署。19项检查通过，包括新增回归、原门控/恢复、惯性初始化/跟踪、图像输入、隔离 ROS 域 IMU/桥接/恢复和前端等价性；新旧核心的3840次对照逐字节一致。这些结果不代表 GitHub CI 或从零构建已通过。
