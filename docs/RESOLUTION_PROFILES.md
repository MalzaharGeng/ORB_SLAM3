# 双目处理分辨率与特征配置

## 配置选择

默认 full 档保持每目 1280×960、1000 特征。可选 light 档使用每目 1216×912、950 特征。
相机采集仍为 MJPEG 2720×960 @30 fps，单 V4L2 缓冲；裁剪、立体校正、物理基线、
相机到机体外参及时间戳生成方式保持一致。缩放发生在校正后、特征提取前。

light 不裁剪视场。焦距和主点按宽高比例缩放，双目 bf 同步为缩放后的 fx×物理基线。
固定空间点的视差也按同一比例变化，物理深度不因配置缩放而改变。

~~~bash
# 仅核对档位与程序路径，不启动相机
VIO_PROCESSING_PROFILE=light bash run_recovery_test.sh --headless --check

# 启动可选轻量档；先停止其他占用相机的采集进程
VIO_PROCESSING_PROFILE=light bash run_recovery_test.sh --headless   --px4-config config/decxin_px4.yaml

# full 为默认，可显式选择
VIO_PROCESSING_PROFILE=full bash run_recovery_test.sh --headless   --px4-config config/decxin_px4.yaml
~~~

轻量档尚不能证明定位精度无损，因此没有替换默认配置。
桥接接收与飞控导航授权条件独立于处理档位，切换档位不会放宽门控。

## 对照结果

平台：Jetson Orin Nano / Ubuntu 22.04 / ROS 2 Humble，CPU 后端。
使用同一段 557 组真实双目图像，各配置独立回放两次，共 4456 帧。
未并行运行多个回放，CUDA 关闭，整段与环形录制关闭。

| 每目尺寸 / 配置特征数 | SLAM 计算中位耗时，两次中位数均值 | 有效位姿帧，两次 | 相对独立 PnP 的帧间旋转误差 P95，两次 |
|---|---:|---|---|
| 1280×960 / 1000 | 90.16 ms | 555、556 / 557 | 0.207°、0.236° |
| 1216×912 / 950 | 87.79 ms | 556、557 / 557 | 0.275°、0.273° |
| 1152×864 / 900 | 80.77 ms | 555、557 / 557 | 0.230°、0.337° |
| 1264×948 / 980 | 92.67 ms | 556、557 / 557 | 0.216°、0.188° |

1216×912 档的计算中位耗时约低 2.6%，平均耗时对应的计算吞吐约提高 3%。
1152×864 档约低 10.4%，但旋转误差波动较大。
1264×948 档没有显示速度收益。实际服务还受取流、校正、桥接、建图和录制影响，
不能把单帧计算吞吐直接写成常驻服务帧率。

每档两次回放末帧均有效，未触发地图完整重置。
原配置重复运行的全局轨迹本身存在明显差异，录制也没有外部真值；
因此未将某次原配置轨迹当作定位精度真值。
独立 PnP 来自原尺寸双目图像，它是交叉检查参考，也不是外部真值。

## 验证与边界

- 原尺寸、95%、90% 三档几何回读检查通过，同比例视差得到相同物理深度。
- full/light 及非法档位的启动器检查通过。
- 4 项既有回归通过：启动器、跟踪窗口、PX4 位姿门控和 IMU 缓冲。
- 可选轻量档的静态相机运行验证仅覆盖启动和图像处理，不代表运动或实飞验收。
- 未进行新配置下的实飞或带真值的精度验证。
- 旋转残差已有变化，不能声称缩放和减特征对定位完全无影响。
- VIO 需要单独验证初始化、连续性和导航融合；纯双目回放结果不替代这些检查。
