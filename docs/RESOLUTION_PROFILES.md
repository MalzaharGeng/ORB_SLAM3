# 双目处理分辨率与特征配置

## 当前配置

DECXIN 的处理下限为每目 960×720、配置特征数 1000。
开机服务显式使用 light：960×720 / 1000，GPU 校正和 FAST，CPU 金字塔层级并行。
纯双目服务采用双缓冲和独立取流；惯性入口强制保留标定单缓冲和原取流方式。
启动器单独运行时仍默认 full：1280×960 / 1000，可作为回退配置。
两个配置均保留 8 层金字塔、1.2 比例、FAST 阈值 20/7，不缩减视场。

相机采集仍为 MJPEG 2720×960 @30 fps、单 V4L2 缓冲。
先裁剪、校正到每目 1280×960，再由 Settings 按比例缩放。
原始内参保留在配置中，Camera.newWidth/newHeight 指定处理尺寸；
运行时 fx、fy、cx、cy 和 bf 一起缩放，物理基线、旋转外参和时间偏移不变。

| 参数 | full | light 的实际处理值 |
|---|---:|---:|
| 尺寸 | 1280×960 | 960×720 |
| fx、fy | 694.006880918 | 520.505160689 |
| cx | 649.014984131 | 486.761238098 |
| cy | 444.565422058 | 333.424066544 |
| bf | 43.843884702 | 32.882913526 |
| 配置 ORB 特征数 | 1000 | 1000 |

同比例视差对应相同物理深度；几何检查通过，参考点深度为 2.19219 m。
实际提取数量会受图像内容及八叉树分配影响，配置数不是低纹理场景的检测数量保证。

~~~bash
# 只检查路径与档位
VIO_PROCESSING_PROFILE=light bash run_recovery_test.sh --headless --check

# 临时停止常驻服务后启动轻量档
VIO_PROCESSING_PROFILE=light ORB_SLAM3_PARALLEL_LEVELS=1 bash run_recovery_test.sh --headless --px4-config config/decxin_px4.yaml

# 全尺寸回退；单独运行启动器默认即为 full
VIO_PROCESSING_PROFILE=full bash run_recovery_test.sh --headless --px4-config config/decxin_px4.yaml
~~~

日常状态内录和自动验证不随处理档位关闭。图像内录默认关闭，可按需显式开启。
切换处理档位不放宽飞控观测发布、惯性成熟度或飞手授权门控。

## 真实记录回放

同一段 557 组双目图像，单任务回放；Jetson Orin Nano，25W 模式，
6 个 CPU 核，CPU 上限 1.344 GHz。图像内录关闭。
在特征数固定 1000 的约束下比较 7 次，共 3899 帧；另有原尺寸基线 2 次、1114 帧。

| 每目尺寸 / 后端 | SLAM 计算中位耗时 | 有效帧 / 557 | 独立 PnP 帧间旋转残差 P95 |
|---|---:|---|---|
| 1280×960，CPU 串行，两次 | 90.52 / 89.80 ms | 555 / 556 | 0.207° / 0.236° |
| 1152×864，CPU 串行 | 82.93 ms | 556 | 0.234° |
| 1080×810，CPU 串行 | 75.25 ms | 556 | 0.398° |
| 960×720，CPU 串行，两次 | 67.14 / 67.55 ms | 556 / 556 | 0.211° / 0.195° |
| 960×720，CUDA FAST 串行 | 66.26 ms | 556 | 0.236° |
| 960×720，CPU 层级并行 | 61.82 ms | 555 | 0.285° |
| 960×720，CUDA FAST + 层级并行 | 62.38 ms | 556 | 0.226° |

各次末帧有效，未触发完整地图重置。
并行 CPU 的计算耗时相对全尺寸基线约下降 31%，但计算吞吐不是常驻服务帧率。
GPU 在缩小后的图像上没有稳定的额外速度收益，因此保留可选 CUDA 后端，默认 CPU。

独立 PnP 使用原尺寸双目图像，是交叉检查参考，不是外部真值。
全局轨迹重复回放本身存在差异，不能将单次基线轨迹视为真值。
旋转残差已有变化，不能据此宣称处理尺寸调整对定位精度完全无影响。

## 带内录的常驻服务

两种后端均开启层级并行、连续原始状态内录、每帧导航记录及导航健康验证，
关闭环形与整段图像编码，使用同一静置场景。

| 配置 | 5 秒窗口 fps 范围 / 中位数 | SLAM 耗时中位数 | 已记录有效导航帧 |
|---|---|---:|---:|
| 960×720 CPU | 12.3–14.4 / 13.2 | 67.2 ms | 1420 / 1420，107.34 s |
| 960×720 CUDA FAST | 12.0–13.9 / 13.2 | 67.0 ms | 1042 / 1042，79.64 s |

同场景全尺寸服务约 10 fps。两种轻量后端实际帧率相当，GPU 采样峰值 49%。
取流耗时中位数约 55.5/57.2 ms，包含等待与灰度 JPEG 解码；校正约 17.7 ms。
采集线程与跟踪线程重叠，不能把三项耗时直接相加解释总帧率。
30 秒资源采样约占 2.3 GiB 内存，温度约 51–52℃，未改变功耗模式或频率上限。
尚未达到 30 fps；后续需继续处理解码、校正和特征提取，不能仅将相机设为 60 fps。

## 验证边界

- 缩放几何、启动器回归、CPU/CUDA 与层级并行的关键点及描述子一致性检查通过。
  一致性覆盖 4 组合成图和 20 张真实图，CUDA 调用计数 26。
- 两次静态服务正常收尾，导航包数与写出数一致，均无有效帧缺失。
- 惯性入口静态检查记录 521 帧、4464 条实际消费 IMU，28 列格式及批次总数一致，
  正常停止后完整写出。该检查未完成 VIBA2。
- 启动器参数保持 IMU 配置与 PX4 配置独立，不会互相覆盖。
- 两项服务已启用开机自启；没有为本次更新执行整机重启。
- 未验证新配置下的长期 VIO、外部真值精度、飞控融合或实飞。
- 默认常驻仍为纯双目，飞控观测发布禁止；静置有效位姿不等于自主飞行就绪。
