Orin Nano 侧部署（nano 分支）

机载计算机上的部署物与现场记录：systemd 单元、守护脚本、D435i 恢复程序、录制与 导出工具、飞控参数建议。VIO 源码在 master，本分支与它没有共同历史， 数值也不复制——内参、外参、桥接阈值一律以 master 的 yaml 为准。

文档

硬件与软件栈 板卡、相机与三套外参的分工、依赖构建方式、时间基准问题 守护与自愈 启动顺序、45 s 心跳与 90 s 判死、相机恢复的边界 录制与地图 环形图像、事件冻结、Atlas 管理与现场命令 飞控侧配置 EKF2_EV_CTRL、时延语义、杆臂与判读注意

部署

sudo install -m 0755 bin/*                   /home/nano/
sudo install -m 0755 sbin/vio-camera-prepare /usr/local/sbin/
sudo install -m 0644 systemd/px4-vio.service /etc/systemd/system/
sudo install -m 0440 -o root -g root systemd/nano-vio-camera-recovery.sudoers \
     /etc/sudoers.d/nano-vio-camera-recovery
sudo systemctl daemon-reload && sudo systemctl enable --now px4-vio.service

启动时序

systemd → fake-hwclock load
        → vio-camera-prepare            重新枚举 D435i，VIO 在跑时跳过
        → vio_daemon.sh
             ├─ 等相机节点（video ≥ 6、hidraw ≥ 1）+ 5 s 稳定窗口
             ├─ 起 MicroXRCEAgent，握手失败整只重启，最多 3 次
             ├─ 起 vio_inrec.py              同步内录 → ~/inrec/
             └─ 起 stereo_inertial_realsense_D435i --console，stdin 由 FIFO 顶住

自愈

  1. [VIO_PERF] 计数 45 s 不增长：图像没进主循环。 冻结最后有效输入、标记 .vio_camera_recover、重启采集。
  2. 日志行数与进程 CPU 时间同时不变 90 s：判死，结束本次 会话，由 systemd 重启。等 IMU 初始化时日志本来就会长时间不增长，所以第二路 证据必须有。
vio-camera-prepare 只处理 8086:0b3a；目标设备正被 VIO 使用时 返回 skipped_running_vio，挡住「复位 → SLAM 崩 → 再复位」循环。 sudoers 只放行这一条无参数命令。

已知限制

  1. RTC 读出 1970，fake-hwclock 记的时间开机被 hctosys 覆盖， 录制文件名停在 inrec_19700101_*；相对时间判读不受影响。
  2. 环形缓冲只在磁盘：最近 20 s 全帧率 + 每 1 s 一组的 120 s 背景，背景的 IMU 批次 不连续，不能复跑惯性。
  3. 5 cm 基线在弱纹理、强反光、远距离与振动下可观测性差，加特征点解决不了。
